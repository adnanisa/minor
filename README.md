# نموذج نظام شئون وأموال القاصرين — Pro Prototype v4

نموذج تفاعلي ثنائي اللغة لبوابة الموظفين الداخلية، أعيد بناؤه استناداً إلى:

- ملاحظات فريق تحليل الأنظمة وتجربة المستخدم الواردة في `Outlook.pdf`.
- المرئيات والأوامر المباشرة على النموذج الواردة في `file1.pdf`.
- تصنيفات الأصول والحقول المشتركة الستة عشر الواردة في الصورة المرفقة `pic1`.
- بيانات ملف التركة وملف المحجور عليه الافتراضية التي زود بها فريق المشروع.

## التشغيل

1. فك ضغط الحزمة.
2. افتح `index.html` في المتصفح.
3. اسم المستخدم وكلمة المرور التجريبيان موجودان مسبقاً، لذلك يمكن الضغط مباشرة على زر الدخول.
4. يمكن أيضاً الضغط على زر eKey التجريبي.
5. تنتقل شاشة الدخول إلى `portal.html`.

## الملفات

- `index.html`: شاشة الدخول الرئيسية.
- `login.html`: نسخة من شاشة الدخول للتوافق مع الروابط السابقة.
- `portal.html`: البوابة الداخلية.
- `styles.css`: نظام التصميم والاستجابة للجوال والكمبيوتر.
- `app.js`: البيانات الافتراضية ومنطق التفاعل الكامل.
- `REQUIREMENTS_COVERAGE.md`: مصفوفة تغطية الملاحظات والمتطلبات.
- `QA_REPORT.md`: نتائج فحص النموذج.
- `qa_results.json`: نتائج الاختبارات الآلية التفصيلية.

## المكونات المنفذة

### الصفحة الرئيسية

- مدخل موحد للوحدات بدلاً من جعلها لوحة خاصة بالملفات فقط.
- فصل المؤشرات القانونية والتشغيلية عن المتابعة المالية.
- بطاقات للوصول إلى الملفات والأصول والعقارات والحسابات والمهام والتقارير.
- أحدث عناصر صندوق العمل والتنبيهات التي تتطلب إجراء.

### مركز الملفات الموحد

- شاشة واحدة لجميع أنواع الملفات مع Views محفوظة وفلاتر.
- الأنواع المنفذة:
  - ملف تركة مسلم.
  - ملف تركة غير مسلم.
  - ملف قاصر مرتبط بتركة.
  - ملف قاصر مستقل.
  - ملف محجور عليه.
  - ملف مسجون.
  - ملف غائب.
- البحث برقم الملف، والرقم الشخصي، وصاحب الملف، وجميع الأطراف المرتبطة.
- فصل الحالة القانونية عن الحالة التشغيلية.
- عرض كامل لتفاصيل الملف ضمن تبويبات مترابطة.

### معالج فتح ملف جديد

- مسارات تعتمد على نوع الملف ومصدره.
- رقم الفريضة الشرعية للتركة المسلمة.
- استرجاع تجريبي من المصدر، مع بيان مصدر كل حقل.
- فحص التكرار قبل الإنشاء.
- تحقق من الرقم الشخصي والتواريخ، ومنع تاريخ وفاة مستقبلي.
- عرض الأطراف المسترجعة وعلاقاتهم.
- المستندات مرحلة مستقلة.
- لا توجد خطوة أصول أثناء فتح الملف.
- مراجعة شاملة قبل إنشاء المسودة.
- رسالة تأكيد قبل فقد بيانات المعالج.

### تفاصيل الملف

- البيانات القانونية والشخصية.
- الأحداث والتواريخ الدلالية؛ لا يوجد حقل عام باسم «التاريخ الأساسي».
- الأطراف مصنفة إلى ورثة، أطراف ذوي علاقة، وأطراف معينين.
- الحساب المساعد والرصيد الحالي لكل مستفيد عند وجود حساب.
- المستندات، التعاميم، الأصول، الحسابات، الأعمال، والتنبيهات وسجل التدقيق.
- نسبة اكتمال مشتقة من نموذج أوزان مستقل لكل نوع ملف.
- إجراء «اعتماد وتكليف» مع خيار قائمة القسم أو موظف محدد وأولوية وملاحظات.

### مركز الأصول المركزي

- سجل أصل واحد يمثل مصدر الحقيقة لجميع الوحدات.
- التصنيفات المعتمدة:
  - عقارية.
  - منقولة، بما فيها غير الملموسة.
  - مالية.
  - تجارية.
  - أخرى.
- الحقول المشتركة الستة عشر منفذة مع حالة الإلزام وقابلية التعديل.
- تسجيل الأصل لا يتاح إلا بعد اعتماد الملف ووجود رد تعميم مؤكد.
- بطاقة أصل كاملة، وخريطة Field-to-Source، ومستندات وسجلات إيراد ومصروف وروابط التنبيهات.

### العقارات

- العقارات تقرأ من سجل الأصل المركزي، وليست سجلاً منفصلاً مكرراً.
- الوحدات، العقود، الفواتير، التحصيلات، المتأخرات، التوزيعات، وشجرة الملكية.
- نسبة الإشغال مشتقة من الوحدات والعقود للفترة، وليست قيمة ثابتة.
- الإيرادات محسوبة من الفواتير وسندات القبض.
- مثال العقار التجاري بأربعة محلات وإيراد شهري 800 د.ب وسنوي 9,600 د.ب.
- تنبيه صريح بأن التقسيم بالتساوي في المثال لا يمثل القسمة الشرعية.

### الأستاذ العام والحسابات المساعدة

- حسابات البنوك، الصندوق، القاصرين، الرشد، المحجور عليهم، والتركات.
- حساب مساعد لكل مستفيد أو صاحب ملف عند الحاجة.
- كشف حركة يشبه كشف البنك ويتضمن المدين والدائن والرصيد الجاري بعد كل سطر.
- زر تفاصيل القيد على مستوى الحركة لعرض جميع سطور القيد وتحقق التوازن.

### صندوق العمل والتنبيهات

- صندوق عمل موحد يوضح النوع والمصدر والمرحلة والإجراء المطلوب وSLA والرابط المباشر.
- قواعد القرار تبقى داخل الوحدة الأصلية.
- كل تنبيه يتضمن المصدر وقاعدة الظهور والاستبعاد والمستلم ومفتاح منع التكرار ودورة الحياة.
- التنبيهات المنفذة تشمل:
  - متوفى لديه قُصّر دون ملف تركة.
  - محجور عليه متوفى.
  - وصول رد على تعميم.
  - تأخر استلام تكليف من قائمة القسم.
  - قضية مرتبطة بقاصر أو طرف في ملف.
  - حساب رشد تجاوز موعد الصرف.
- فصل التنبيهات الحدثية عن التقارير والقوائم التجميعية.

### التقارير

ثمانية تقارير قابلة للتشغيل مع فلاتر فترة زمنية ونتائج فعلية داخل النموذج، مع تصدير CSV:

- حالة الملفات والاكتمال.
- دورة حياة التنبيهات وSLA.
- مبالغ الرشد غير المصروفة.
- حصر الأصول ودرجة الموثوقية.
- إيرادات وإشغال العقارات.
- التعاميم والردود.
- أداء صندوق العمل.
- التدقيق وإعادة التكليف.

## اللغة والاستجابة

- العربية والإنجليزية.
- RTL للعربية وLTR للإنجليزية.
- الأرقام العربية الهندية عند اختيار العربية، والأرقام اللاتينية عند اختيار الإنجليزية.
- القائمة الجانبية قابلة للضغط والتمرير اللمسي على الجوال.
- الجداول تتحول إلى بطاقات واضحة على الشاشات الصغيرة.

## التهيئة لـ Oracle APEX

هيكل الواجهة يحاكي Universal Theme:

- Header Bar.
- Tree Navigation.
- Breadcrumb Region.
- Cards / KPI Regions.
- Interactive Report / Interactive Grid placeholders.
- Modal Dialogs وRight-side Drawers.
- Shared Components متوقعة للترجمة والقوائم والصلاحيات.

عند النقل إلى APEX يجب استبدال المصفوفات داخل `app.js` بجداول وViews وREST Data Sources أو Packages، وتنفيذ البحث والفلاتر والترقيم على مستوى الخادم.

## حدود النموذج

- لا يوجد ربط حقيقي مع eKey أو هيئة المعلومات أو الفريضة الشرعية أو المحاكم أو المؤسسات الإصلاحية أو الجهات المالية؛ المعروض محاكاة واضحة للمصدر المتوقع.
- البيانات كلها افتراضية ولا تخص أشخاصاً حقيقيين.
- الأنصبة المتساوية في مثال التركة للعرض فقط ولا تمثل القسمة الشرعية.
- المصادر المرفقة لم تحدد جميع الحقول القانونية التفصيلية لمسارات التركة غير المسلمة والمسجون والغائب؛ لذلك تم تمثيل الهيكل الأساسي مع وسم الحاجة إلى اعتماد نهائي من المختصين، دون اختراع قواعد قانونية غير مقدمة.
- التخزين الحالي داخل الذاكرة أثناء الجلسة، لأن الهدف نموذج تفاعلي وليس نظام إنتاج.
